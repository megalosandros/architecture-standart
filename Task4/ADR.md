### <a name="_u8xz25hbrgql"></a>**Нефункциональные требования**

| **№**  | **Требование**                       |
| :----: | :----------------------------------- |
| **R**  | **Надёжность (Reliability)**         |
| R01    | Общая доступность пользовательских каналов (сайт + интернет-банк + Deposits Gateway) — не ниже 99,9% |
| R02    | Поддержка автоматического переключения на резервный ЦОД при недоступности основного (в течение ≤ 5 минут). |
| R03    | Гарантия доставки заявки: даже при сбое одного из компонентов (например, Kafka или кол-центра) заявка не теряется и может быть восстановлена. |
| R04    | Целостность данных ставок: файл, отправляемый партнёрскому кол-центру, должен быть полным и соответствовать состоянию на момент выгрузки. |
| R05    | При недоступности SFTP-сервера партнёра — система повторяет отправку до 3 раз с экспоненциальной задержкой и оповещает администратора при окончательном сбое. |
| R06    | Все критические операции (подача заявки, обновление ставок) — логируются с возможностью аудита. |
| **P**  | **Производительность (Performance)** |
| P01    | API Deposits Gateway должен обрабатывать не менее 50 запросов в минуту с 95-м перцентилем времени ответа ≤ 400 мс. |
| P02    | Генерация и отправка файла ставок партнёру — не дольше 30 секунд после запуска задачи. |
| P03    | Веб-интерфейс кол-центра банка отображает актуальные ставки мгновенно (данные кешируются или загружаются при открытии сессии). |
| P04    | Архитектура Deposits Gateway поддерживает горизонтальное масштабирование. |
| **+R** | **+Ограничения (Restrictions)**      |
|  +R01  | Отсутствие возможности реализации API для партнёрского кол-центра — обмен данными только через файлы (SFTP). |
|  +R02  | Передача файла партнёрскому кол-центру — только по SFTP с аутентификацией по SSH-ключу. | 
|  +R03  | Доступ к Admin UI и API Deposits Gateway — только по внутренней сети банка с аутентификацией. |
|  +R04  | Новые компоненты должны использовать технологии с внутренней экспертизой: Java 11+, Spring Boot, MS SQL, React. |


### <a name="_qmphm5d6rvi3"></a>**Решение**

В рамках уже существующего Deposits Gateway добавляются два новых компонента:

1. Admin UI для управления ставками
   * Веб-интерфейс для сотрудников депозитного отдела.
   * Позволяет редактировать/загружать ставки (вручную или из Excel).
   * Сохраняет данные в таблицу deposit_products (MS SQL).
2. Rate Distribution Service
   * Ежедневно (по расписанию) выполняет две задачи:
       1. Пушит ставки в систему кол-центра банка через её существующий API (Java Spring Boot → PostgreSQL).
       2. Генерирует CSV-файл и отправляет его по SFTP в папку партнёрского кол-центра.

Такое решение:
 - Использует уже созданный Deposits Gateway (единый источник ставок).
 - Не требует изменений в АБС или Excel-процессах на MVP.
 - Поддерживает оба типа кол-центров: внутренний (API) и внешний (файл).

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

<b>Альтернатива 1. Продолжать рассылать Excel по email</b>

<b>Плюсы:</b> Простота реализации, привычная схема работы.

<b>Минусы:</b> Ненадёжно, нет контроля версий, нарушает безопасность.

<b>Альтернатива 2. Создать отдельный "Сервис ставок"</b>

<b>Плюсы:</b> Чёткое разделение ответственности.

<b>Минусы:</b> Увеличивает сложность, дублирует функционал Deposits Gateway.

<b>Альтернатива 3. Интегрировать партнёра через API</b>

<b>Плюсы:</b> Более современно.

<b>Минусы:</b> Партнёр не поддерживает API — технически невозможно.


**Недостатки, ограничения, риски**

<b>Недостатки:</b>

* Дублирование данных: Ставки, продукты и заявки временно хранятся вне АБС (в MS SQL Deposits Gateway).  
* Фрагментация пользовательского опыта: Клиент подаёт заявку онлайн, но завершает процесс офлайн.  
* Зависимость от асинхронной доставки: Кол-центры получают ставки с задержкой, что может привести к консультациям по устаревшим условиям в день изменения ставок.  

<b>Ограничения</b>

* Партнёрский кол-центр не поддерживает API-интеграцию: Технологические возможности внешнего поставщика.  
* Запрет на доработку ядра интернет-банка со стороны подрядчика: Бюджетные и организационные ограничения.  
* Отсутствие централизованного каталога продуктов в АБС: Бизнес-процессы банка исторически не предусматривали digital-каналы.  

<b>Риски:</b>

* Сбой при отправке файла партнёру → устаревшие ставки  
* Перегрузка кол-центра звонками → падение SLA  
* Ошибка администратора при ручном обновлении ставок
